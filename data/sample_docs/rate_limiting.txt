API Rate Limiting and Throttling

Rate limiting protects services from abuse and ensures fair resource allocation. Common algorithms include token bucket, leaky bucket, fixed window, and sliding window counters. Each algorithm trades off burst handling and memory efficiency.

Token bucket allows bursts up to bucket capacity while enforcing average rate. Sliding window counters provide smoother enforcement with moderate memory. Distributed rate limiting requires shared state, often via Redis or consistent hashing.

Headers such as X-RateLimit-Limit, X-RateLimit-Remaining, and Retry-After communicate limits to clients. 429 Too Many Requests signals throttling. Backoff with jitter reduces thundering herd problems.

Tiered limits by API key or user plan enable monetization. Observability of limit hits informs capacity planning. Graceful degradation and queueing improve resilience under peak load.
